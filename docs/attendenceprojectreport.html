📋 1. Project Overview

▼

Project Name

Automated Attendance System — An AI-powered face recognition and QR-code based attendance management system.

Elevator Pitch (30 seconds)

💡 30-Second Pitch "Our project is an AI-powered Attendance System that uses FaceNet deep learning to automatically recognize registered students via webcam and mark their attendance. It also offers a QR code fallback method. Built with Flask, PostgreSQL, and PyTorch, it eliminates proxy attendance and manual roll calls entirely."

1-Minute Explanation

This system solves the traditional attendance problem in educational institutions. Admins log in securely, register students with their details, capture their face embeddings using the MTCNN + FaceNet (InceptionResnetV1) pipeline, and store 512-dimensional face vectors in PostgreSQL. During attendance, the webcam feed is processed frame-by-frame — faces are detected via MTCNN, embeddings are extracted using FaceNet, and cosine similarity is used to match against stored student embeddings. If the similarity score exceeds 0.70, attendance is automatically marked. A QR code attendance path is also available for mobile devices.

3-Minute Explanation

The system is a full-stack Flask web application with three Blueprints: main (auth + navigation), student (registration + face capture), and attendance (recognition + records). The AI pipeline uses facenet-pytorch's MTCNN for multi-task face detection and InceptionResnetV1 pre-trained on VGGFace2 for generating 512-dimensional face embeddings. During registration, 5 face captures are averaged into a single embedding stored as JSON in PostgreSQL. During recognition, OpenCV's CSRT tracker maintains face positions between detection frames (every 10th frame runs MTCNN, rest use tracking) to keep the UI smooth. Multiple safety filters are applied: brightness checks, confidence thresholds (0.95 for MTCNN, 0.70 for cosine similarity), minimum face size (50×50px), flat surface rejection, and embedding norm validation. Admin authentication uses Werkzeug password hashing with a 3-attempt lockout mechanism. The QR flow generates QR codes pointing to a mobile page where students enter their roll number to mark attendance.

5-Minute Explanation

Extends the 3-minute version with: The Flask application factory pattern (create_app()) initializes the app, configures SQLAlchemy with PostgreSQL, imports models (Admin, Student, Attendance), and registers three Blueprints. Database schema uses three tables: admins (id, email, hashed_password), students (id, roll, first_name, last_name, department, year, email, embedding as TEXT), and attendance (id, roll, method, timestamp). The roll number is auto-generated as {year}{DEPT}{sequential_count}. IST timezone is handled manually via UTC+5:30 offset. The frontend uses vanilla HTML/CSS/JavaScript with Jinja2 templates, Canvas API for drawing face bounding boxes, and getUserMedia for webcam access. Client-side tracking smooths bounding boxes using linear interpolation (alpha=0.65–0.75). Attendance is restricted to once per student per day via database-level date filtering. Records are grouped by date with latest-first sorting. Cache-control headers prevent back-button access to dashboard after logout.

Problem Statement

Manual attendance systems in educational institutions are slow, error-prone, and susceptible to proxy attendance. This project automates attendance marking using facial recognition AI, eliminating human error and fraud.

Motivation

  • Eliminate proxy attendance in colleges and universities
  • Save time compared to manual roll calls
  • Provide an accessible alternative (QR code) when camera-based recognition isn't feasible
  • Demonstrate practical application of deep learning in real-world systems

Use Cases

  • College classroom attendance
  • Lab session tracking
  • Event participation verification
  • Corporate meeting attendance

Target Users

  • Admins: Teachers/professors who register students and view attendance
  • Students: Who get their faces registered and attendance marked automatically or via QR

Features

Feature Method Priority
Admin Login/Register Werkzeug hash + session 🟢 Core
Student Registration Form → API → PostgreSQL 🟢 Core
Face Capture & Embedding MTCNN + FaceNet 🟢 Core
Face Recognition Attendance Cosine similarity ≥ 0.70 🟢 Core
QR Code Attendance QR → mobile → verify → mark 🟡 Secondary
Dashboard Analytics Total/Present/Absent counts 🟢 Core

Limitations

  • No JWT — uses server-side Flask sessions
  • Secret key is hardcoded ("secret123")
  • No role-based access control (single admin role only)
  • Linear scan of all students for matching — O(n) per face per frame
  • No liveness detection — vulnerable to photo spoofing
  • QR flow doesn't verify identity (any student can enter any roll number)

Future Scope

  • Add liveness detection (blink detection, 3D depth)
  • Implement FAISS/Annoy for O(log n) embedding search
  • Add JWT-based token authentication
  • Deploy with Docker + cloud (AWS/GCP)
  • Add email notifications for absent students
  • Implement role-based access control

Why Flask over Django?

  • Lightweight: Flask is a micro-framework — perfect for this project's scope
  • Flexibility: No enforced project structure; Blueprint pattern chosen deliberately
  • Faster prototyping: Less boilerplate than Django
  • Trade-off: Django provides admin panel, ORM migrations, auth out-of-box; Flask requires manual setup

Why PostgreSQL over MySQL/SQLite?

  • TEXT columns: Efficient storage of large JSON embedding strings (~4KB per student)
  • Robustness: ACID compliance, concurrent connections
  • Production-ready: Better than SQLite for multi-user scenarios

Why PyTorch over TensorFlow?

  • FaceNet-PyTorch library: The chosen library is PyTorch-native
  • Dynamic computation graph: Easier debugging than TF 1.x static graphs
  • Research-friendly: Dominant in academic face recognition research

🎤 Interview Q: "Why facenet-pytorch instead of dlib or DeepFace?" Answer: facenet-pytorch provides both detection (MTCNN) and recognition (InceptionResnetV1) in a single package with PyTorch integration. It's pre-trained on VGGFace2 (3.3M face images), giving high accuracy without custom training. dlib's face_recognition library uses a different architecture and is slower. DeepFace is a wrapper library with more overhead.

🧠 6. AI / Machine Learning

▼

Model Architecture

The project uses two models from the facenet-pytorch library:

MTCNN (Multi-task Cascaded CNN)
  • Purpose: Face detection + alignment
  • Architecture: 3-stage cascade: P-Net → R-Net → O-Net
  • Output: Bounding boxes + 5 facial landmarks
  • Config in project: keep_all=True, min_face_size=20, thresholds [0.4, 0.5, 0.5]
InceptionResnetV1
  • Purpose: Face embedding extraction
  • Architecture: Inception-ResNet hybrid (deep CNN)
  • Pre-trained on: VGGFace2 (3.3M images, 9131 subjects)
  • Output: 512-dimensional embedding vector
  • Mode: .eval() — inference only, no training

Dataset

The project uses a pre-trained model (transfer learning). No custom dataset or training is performed. The VGGFace2 dataset was used to pre-train InceptionResnetV1 before the library was published.

Training

Not performed in this project. The model is used in inference-only mode (.eval()). The original training was done by the facenet-pytorch library authors using triplet loss on VGGFace2.

Inference Pipeline

# Step 1: Receive base64 image from browser
img = base64.b64decode(image_data)
frame = cv2.imdecode(np.frombuffer(img, np.uint8), cv2.IMREAD_COLOR)

# Step 2: BGR → RGB conversion (OpenCV uses BGR, MTCNN expects RGB)
rgb = cv2.cvtColor(frame, cv2.COLOR_BGR2RGB)

# Step 3: MTCNN detects face bounding boxes
boxes, probs = mtcnn.detect(rgb)

# Step 4: Crop face region, convert to PIL Image
face = frame[y:y+h, x:x+w]
img = Image.fromarray(cv2.cvtColor(face, cv2.COLOR_BGR2RGB))

# Step 5: MTCNN extracts aligned face tensor (160×160)
face_tensor = mtcnn(img)  # Returns [3, 160, 160] tensor

# Step 6: InceptionResnetV1 generates 512-d embedding
emb = resnet(face_tensor.unsqueeze(0))  # [1, 512]
embedding = emb.detach().numpy()[0]      # [512,]

Preprocessing

  • Color conversion: BGR (OpenCV) → RGB (MTCNN requirement)
  • Face alignment: MTCNN automatically aligns faces using 5 landmarks
  • Resize: MTCNN outputs 160×160 pixel face crops
  • Normalization: Done internally by MTCNN (pixel values → [-1, 1])

Embeddings

A face embedding is a 512-dimensional float vector that represents a face's unique identity in a high-dimensional space. Faces of the same person cluster together; different people are far apart.

  • Dimension: 512
  • Storage: JSON-serialized string in PostgreSQL TEXT column (~4KB)
  • Registration: 5 captures → 5 embeddings → averaged into 1 representative embedding

Cosine Similarity

def cosine_similarity(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))
  • Range: [-1, 1] — where 1 means identical, 0 means orthogonal
  • Threshold: 0.70 (match), 0.75 (auto-attendance in capture.js)
  • Why cosine over Euclidean: Cosine is scale-invariant; measures direction, not magnitude. Robust to variations in lighting/embedding magnitude.

CSRT Tracker (OpenCV)

Used between MTCNN detection frames (MTCNN runs every 10th frame). CSRT (Channel and Spatial Reliability Tracking) maintains bounding box positions for smooth UI without re-running expensive neural network inference.

Safety Filters in the AI Pipeline

Filter Value Purpose
Brightness check < 40 mean Reject low-light frames
MTCNN confidence < 0.95 Reject uncertain detections
Min face size 50×50 px Reject tiny/far faces
Flat surface (std dev) < 20 Reject non-face regions
Embedding norm < 0.5 Reject weak embeddings
Cosine similarity < 0.70 Reject poor matches

AI Concepts Not Used in This Project

  • Custom Training / Fine-Tuning: Not used — pre-trained model only
  • RAG / LLM / Prompt Engineering: Not used — this is a computer vision project
  • Classification / Regression heads: Not used — embedding comparison via similarity
  • Tokenization: Not used — no NLP component
  • FAISS / Annoy (Vector Search): Not used — linear scan over all students
🎤 Deep Viva: "What is the difference between face detection and face recognition?" Detection (MTCNN) finds WHERE faces are in an image — outputs bounding boxes. Recognition (FaceNet/InceptionResnetV1) determines WHO the face belongs to — outputs an embedding that is compared against stored embeddings. Detection is a prerequisite for recognition.
🎤 Deep Viva: "Why average 5 embeddings instead of storing all 5?" Averaging reduces noise from individual captures (lighting, angle variations). A single average embedding is more robust and reduces storage + comparison time. Trade-off: loses ability to match against multiple distinct poses.

Authentication

  • Method: Flask server-side sessions (session["admin"])
  • Password storage: Werkzeug's generate_password_hash() (PBKDF2 + SHA256)
  • Login verification: check_password_hash(stored, input)
  • Account lockout: 3 failed attempts → locked (in-memory dict, resets on server restart)

Route Protection

@main_bp.before_app_request
def block_unauthorized():
    protected_routes = ["/dashboard", "/register_page", "/capture",
                        "/recognize_page", "/records_page", "/qr_session"]
    if request.path in protected_routes:
        if "admin" not in session:
            return redirect("/")

Business Logic Highlights

  • Roll number generation: {year}{DEPT}{count_padded_to_3} — e.g., 2024CSE001
  • Duplicate attendance prevention: Checks if attendance exists for same roll + same date before inserting
  • IST timezone: datetime.utcnow() + timedelta(hours=5, minutes=30)
  • Cache-control headers: Prevents browser back-button access after logout

Error Handling

Try-except blocks around all route handlers. Errors are logged to console via print() and JSON error responses are returned. Database operations include db.session.rollback() on failure.

❌ Common Mistakes
  • Saying "the project uses JWT" — it doesn't, it uses Flask sessions
  • Saying "bcrypt is used for hashing" — it's Werkzeug's PBKDF2
  • Forgetting that login_attempts dict resets on server restart

▼

Entry Point: run.py

from app.extensions import db

App Factory: app/__init__.py

Uses the Application Factory Pattern — a Flask best practice that prevents circular imports and enables testing with different configurations.

  1. Creates Flask instance
  2. Loads Config class
  3. Sets SECRET_KEY
  4. Initializes SQLAlchemy with db.init_app(app)
  5. Imports models (after db init to avoid circular imports)
  6. Imports and registers 3 Blueprints
  7. Calls db.create_all() within app context

Key Function: recognize_with_box (Most Complex)

Time Complexity: O(F × S) per frame where F = faces detected, S = total students. For 3 faces and 100 students, that's 300 cosine similarity calculations per detection frame.

Space Complexity: O(S) for loading all student embeddings into memory per detection cycle.

Key Function: compare_embeddings

def compare_embeddings(inp, stored):
    best = -1
    for e in stored:
        score = cosine_similarity(np.array(inp), np.array(e))
        if score > best:
            best = score
    return best, best >= THRESHOLD  # THRESHOLD = 0.7

Note: This function exists in ai/comparator.py but is NOT used in the main recognition flow. The recognition route implements its own inline comparison loop. This is a code redundancy.

Key Function: generate_roll

def generate_roll(year, dept):
    count = Student.query.filter_by(year=year, department=dept).count() + 1
    return f"{year}{dept.upper()}{str(count).zfill(3)}"

Potential Issue: Race condition if two registrations happen concurrently — both might get the same count. Not a problem in single-server deployments.

🎯 12. Design Decisions

▼
Decision Choice Made Why Trade-off
Architecture Monolithic Flask Simple, fast to develop, single deployment Not scalable to microservices without refactor
ML Framework facenet-pytorch (pre-trained) No training data needed, high accuracy Large model size (~100MB), slow on CPU
Embedding Storage JSON in TEXT column Simple, no additional infrastructure Not searchable, no vector indexing
Matching Linear scan + cosine similarity Simple implementation O(n) per face — doesn't scale beyond ~1000 students
Tracking OpenCV CSRT + every-10th-frame detection Reduces GPU/CPU load 10-frame lag for new faces entering the view
Auth Flask sessions (no JWT) Simple for server-rendered pages Not suitable for mobile/SPA with separate API server
QR Code External API (qrserver.com) No library needed Requires internet, external dependency
Frontend Vanilla JS (no framework) Lightweight, no build step Harder to maintain at scale

⚡ 14. Performance

▼

Optimizations Present

  • MTCNN every 10th frame: Reduces expensive neural network calls by 90%
  • CSRT tracker: Lightweight CPU-based tracking between detection frames
  • JPEG compression: Browser sends compressed base64 instead of raw pixels
  • Client-side frame throttling: setTimeout(detect, 250) = ~4 FPS max
  • Embedding averaging: Single comparison per student instead of 5
  • Ghost tracker cleanup: Removes stale trackers to prevent memory leaks

Bottlenecks

  • Linear student scan: O(n) per face per detection — use FAISS for O(log n)
  • Synchronous inference: Flask runs single-threaded by default — blocks during ML
  • No caching: Dashboard data queries DB on every request
  • Base64 overhead: ~33% larger than binary image data

Not Used in This Project

  • Redis caching: Not used
  • Lazy loading: Not used
  • CDN: Not used
  • Multithreading / async: Not used (Flask default single-thread)
  • GPU acceleration: Supported but falls back to CPU if CUDA unavailable

🏢 19. TCS Interview Questions (50 Questions)

▼

Architecture & Design (1-10)

1. What is the overall architecture? 🟢

Monolithic Flask web app with 3 Blueprints (main, student, attendance), PostgreSQL database, and an embedded MTCNN + FaceNet AI pipeline.

2. Why Flask over Django? 🟢

Flask is lightweight and flexible. This project doesn't need Django's admin panel, built-in auth, or ORM migrations. Blueprint pattern provides enough structure.

3. What is the Application Factory Pattern? 🟢

create_app() creates the Flask instance, loads config, initializes extensions, and registers blueprints. Prevents circular imports and enables testing with different configs.

4. How are models imported without circular dependencies? 🟡

Models are imported INSIDE create_app() AFTER db.init_app(app) — not at the top of __init__.py. This ensures db is ready before model definitions execute.

5. What design patterns are used? 🟡

Application Factory, Blueprint, MVC (Models → routes/controllers → templates/views), ORM pattern, Observer pattern (before_app_request).

6. Why store embeddings as JSON in TEXT column? 🟢

Simplicity — no vector database needed. Trade-off: can't do database-level similarity search, requires loading into Python memory for comparison.

7. How does the QR attendance flow work? 🟡

Admin opens QR page → QR code generated pointing to /qr_mobile → Student scans on phone → Enters roll → Verified against DB → Confirms → Attendance marked with method="QR".

8. Why use 3 separate Blueprints? 🟡

Separation of concerns: main_bp handles auth and navigation, student_bp handles registration and face capture, attendance_bp handles recognition and records. Makes code maintainable.

9. What is a Blueprint in Flask? 🟢

A Blueprint is a way to organize Flask routes into separate modules. Like a mini-app that gets registered with the main Flask app. Enables modular code organization.

10. How is the roll number generated? 🟡

{year}{DEPARTMENT}{sequential_count_padded_to_3}. Example: 2024CSE001. Count is based on existing students in same year+department.

AI/ML (11-20)

11. What is MTCNN? 🟢

Multi-task Cascaded Convolutional Networks — a 3-stage cascade (P-Net, R-Net, O-Net) for face detection. Outputs bounding boxes and 5 facial landmarks simultaneously.

12. What is FaceNet / InceptionResnetV1? 🟢

A deep CNN that maps face images to 512-dimensional embedding vectors. Pre-trained on VGGFace2 dataset (3.3M images). Faces of the same person have high cosine similarity.

13. Why cosine similarity over Euclidean distance? 🟢

Cosine measures angle between vectors (direction), ignoring magnitude. More robust to variations in embedding scale. Range is [-1,1], easy to threshold.

14. What is the similarity threshold and why 0.70? 🟢

0.70 is a balance between false positives (too low) and false negatives (too high). The auto-mark threshold in capture.js is 0.75 for extra safety.

15. What is transfer learning? How is it used here? 🟢

Using a model pre-trained on one task (VGGFace2 face recognition) and applying it directly to our task without retraining. The InceptionResnetV1 is used in inference-only mode.

16. What is a face embedding? 🟢

A compact numerical representation (512 floats) of a face's identity. Similar faces have similar embeddings in the vector space. It's like a fingerprint for faces.

17. Why average 5 face captures? 🟡

Reduces noise from individual captures (lighting, angle). The averaged embedding is a more robust representation of the student's face. Follow-up: trade-off is losing multi-pose matching ability.

18. What are the safety filters in recognition? 🟢

Brightness > 40, MTCNN confidence > 0.95, face size > 50×50, standard deviation > 20 (rejects flat surfaces), embedding norm > 0.5.

19. What is the CSRT tracker? Why use it? 🟡

Channel and Spatial Reliability Tracker — a CPU-efficient OpenCV tracker that maintains bounding boxes between expensive MTCNN detection frames. Runs every frame while MTCNN runs every 10th frame.

20. What is VGGFace2? 🟡

A large-scale face dataset with 3.3M images of 9,131 subjects. Used to pre-train InceptionResnetV1. Provides diverse pose, age, and ethnicity coverage.

Backend & Database (21-30)

21. How is authentication implemented? 🟢

Werkzeug PBKDF2+SHA256 password hashing. Flask sessions store admin email. before_app_request middleware checks session on protected routes.

22. What is SQLAlchemy? Why use an ORM? 🟢

Object-Relational Mapper — maps Python classes to database tables. Prevents SQL injection, provides database-agnostic queries, cleaner code than raw SQL.

23. Explain the database schema. 🟢

3 tables: admins (auth), students (details + embedding), attendance (roll, method, timestamp). No explicit foreign keys — relationship enforced at application level.

24. How is duplicate attendance prevented? 🟢

Attendance.query.filter(roll==roll, func.date(timestamp)==today).first() — checks if record exists for same student on same date. Returns "already marked today" if found.

25. How is timezone handled? 🟡

datetime.utcnow() + timedelta(hours=5, minutes=30) — manual IST calculation. Not ideal; should use pytz or zoneinfo for proper timezone handling.

26. What happens on server restart with account lockout? 🟡

The lockout resets because login_attempts is stored in a Python dictionary (in-memory). It should be stored in Redis or the database for persistence.

27. What is the before_app_request hook? 🟡

A Flask callback that runs before every request to the app. Used here as middleware to check if the user is authenticated before accessing protected routes.

28. How are attendance records grouped? 🟡

The /records endpoint groups by date (YYYY-MM-DD), keeps only the latest record per student per day, and returns a JSON object with date keys.

29. What is db.session.rollback()? 🟡

Reverts all uncommitted database changes in the current session. Used in except blocks to prevent partial writes when an error occurs mid-transaction.

30. How is the embedding stored and retrieved? 🟢

Stored: json.dumps(embedding.tolist()) — numpy array → list → JSON string → TEXT column. Retrieved: json.loads(self.embedding) → Python list → np.array() for comparison.

Frontend & Security (31-40)

31. How does the webcam capture work? 🟢

navigator.mediaDevices.getUserMedia({video: true}) starts the camera. Canvas draws video frames, converts to base64 JPEG via toDataURL(), sends to server.

32. How are face boxes drawn? 🟢

Canvas overlay positioned over the video element. After receiving box coordinates from server, JavaScript scales them to display dimensions and uses ctx.strokeRect().

33. What is Jinja2 template inheritance? 🟡

{% extends "base.html" %} inherits the layout (nav, container). {% block content %} defines page-specific content. Avoids HTML duplication.

34. Why use localStorage for roll number? 🟡

Passes data between register→capture pages and QR mobile→verify pages without URL parameters. Persists across page navigations. Cleaned up after use.

35. What security vulnerabilities exist? 🟢

Hardcoded secret key, no CSRF protection, no HTTPS, no input sanitization in JS (innerHTML), no liveness detection, in-memory lockout, no rate limiting.

36. What is CSRF and why is it missing? 🟢

Cross-Site Request Forgery — attacker tricks user's browser into making requests. Missing because no CSRF tokens in forms/API calls. Fix: use Flask-WTF.

37. How does password hashing work? 🟢

Werkzeug uses PBKDF2-SHA256 with random salt. generate_password_hash(password) creates hash. check_password_hash(hash, password) verifies without exposing the original.

38. Why no-cache headers on dashboard? 🟡

Prevents browser from caching the dashboard page. Without this, pressing the back button after logout would show the cached dashboard page.

39. What is the Box smoothing in capture.js? 🟡

Linear interpolation: new = prev + (curr - prev) * alpha. alpha=0.65 gives smooth transitions. Prevents jittery bounding boxes between frames.

40. How does the track matching algorithm work? 🟡

Compares center points of new detections vs existing tracks. If distance < DIST_THRESHOLD (100px), updates existing track. Otherwise creates new track. Tracks age and are removed after MAX_AGE frames or FACE_TIMEOUT ms.

Advanced & System Design (41-50)

41. How would you handle 1000+ students? 🟢

Replace linear scan with FAISS (Facebook AI Similarity Search) for approximate nearest neighbor. Pre-build an index of all embeddings. Search in O(log n) instead of O(n).

42. How would you prevent photo spoofing? 🟢

Add liveness detection: blink detection, head movement challenges, infrared depth sensing, or 3D face reconstruction. Current project has no liveness check.

43. How would you deploy this in production? 🟡

Dockerize → Gunicorn (4 workers) → Nginx reverse proxy → SSL certificate → PostgreSQL managed instance → Environment variables for secrets → CI/CD pipeline.

44. What is the difference between .eval() and .train()? 🟡

.eval() disables dropout and uses running batch norm statistics (inference mode). .train() enables dropout and updates batch norm statistics. Our model uses .eval() because we're only doing inference.

45. What is the difference between MTCNN detect() and forward()? 🟡

detect() returns bounding boxes and probabilities. mtcnn(img) (forward call) returns aligned, cropped face tensors ready for the embedding model.

46. How would you add real-time notifications? 🔴

WebSockets (Flask-SocketIO) for real-time push when attendance is marked. Admin dashboard updates live without polling.

47. What happens if two students look alike? 🟢

The system picks the highest cosine similarity match above 0.70 threshold. If both are close, it might misidentify. Solution: add secondary verification (OTP/QR) or raise threshold.

48. How would you add unit tests? 🟡

Use pytest + Flask test client. Create a test config with SQLite in-memory. Test each API endpoint with mock data. Use unittest.mock for AI pipeline.

49. What is psycopg2-binary? 🔴

A PostgreSQL adapter for Python. "binary" means it includes pre-compiled C extensions (no build tools needed). SQLAlchemy uses it internally to communicate with PostgreSQL.

50. Explain the complete data flow from registration to attendance. 🟢

Register (form → POST /register → generate roll → insert student) → Capture (webcam → 5× POST /capture_face → collect embeddings → POST /save_face_data → average → store JSON) → Recognize (webcam → POST /recognize_with_box → MTCNN detect → FaceNet embed → cosine match → return results) → Mark (POST /mark_attendance → check duplicate → insert record).

⚔️ 23. Cross Questions & Project Defense

▼

Q: "Your project has no liveness detection. Can't someone just hold up a photo?"

A: "Yes, that's a known limitation. In the current version, the flat-surface filter (std dev < 20) provides minimal protection against printed photos, but it won't stop a phone screen photo. For production, I would add infrared depth sensing, blink detection, or challenge-response (ask user to turn head). This was a deliberate scope decision for the academic project."

Q: "Your SECRET_KEY is hardcoded. Isn't that a security risk?"

A: "Absolutely. In production, SECRET_KEY should come from an environment variable or a secrets manager (AWS Secrets Manager, HashiCorp Vault). The hardcoded key is for development convenience only. I'm aware this is a critical security gap."

Q: "Why no CSRF protection?"

A: "The project uses JSON APIs with fetch() calls rather than HTML forms, which are the primary CSRF target. However, APIs are still vulnerable to CSRF if cookies are used for auth (which Flask sessions do). The fix is Flask-WTF's CSRFProtect or switching to token-based auth (JWT)."

Q: "What happens when the server restarts during account lockout?"

A: "The lockout resets because it's stored in a Python dictionary in memory. This is a known limitation. In production, I'd store attempt counts in Redis with TTL expiry, or in the admins database table."

Q: "Your linear scan won't scale. What's your plan?"

A: "For up to 500 students, linear scan is acceptable (~2ms per comparison × 500 = ~1 second). Beyond that, I would use FAISS (Facebook AI Similarity Search) to build an index of embeddings and perform approximate nearest neighbor search in O(log n). Alternatively, Milvus or Pinecone for managed vector search."

Q: "The QR flow has no identity verification. Any student can enter any roll number."

A: "Correct. The QR flow trusts the roll number input. To fix this, I'd add: (1) Time-limited session tokens in the QR data, (2) OTP verification via email/phone, or (3) A quick face verification step on the mobile page."

Q: "Why didn't you use React or Vue for the frontend?"

A: "The project scope didn't require SPA features. Vanilla JS with Jinja2 server-side rendering is simpler to deploy (no build step), easier to maintain for this scale, and reduces the learning curve. For a larger project with complex state management, React would be a better choice."

Q: "Your attendance.roll has no foreign key constraint. Why?"

A: "This is a design gap. The relationship is enforced at the application level (we always verify student existence before marking). However, database-level foreign key constraints provide additional data integrity guarantees. I'd add db.ForeignKey('students.roll') in a production version."

Q: "How accurate is your face recognition?"

A: "InceptionResnetV1 pre-trained on VGGFace2 achieves ~99.65% accuracy on the LFW benchmark. In our project, accuracy depends on lighting, camera quality, and angle. The multiple safety filters (confidence thresholds, brightness checks) reduce false positives at the cost of occasionally missing valid faces."

Q: "What if two people have very similar faces?"

A: "The system picks the best cosine similarity match. For identical twins with similarity > 0.70 to each other's embeddings, there's a risk of misidentification. Solution: raise threshold to 0.85, add secondary verification, or use multi-modal biometrics (face + fingerprint)."
